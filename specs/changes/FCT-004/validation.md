## 1. Verification Tiers (Automated Offline vs Authorized Human-Operated Pilot)

| Tier | Scope & Mechanism | Active Policy Mapping | Closure Effect |
| :--- | :--- | :--- | :--- |
| **1. G3 Spec Baseline** | All `8` requirements, `21` ACs, and `18` test scenarios mapped as `PLANNED` in `traceability.json`. | `spec-hygiene` | Mandatory for Gate G3 (`Implementation Readiness`) exit. |
| **2. `FCT-004A` Automated Offline / Loopback Verification** | Pure Kotlin `PilotAuthorizationGate` / `ReadOnlyPilotGuard`, `AuthorizedPilotEndpointTrustPolicy` negative origin/IPv4/IPv6 CIDR/TLS tests, capability-restricted HTTP & WS `MockWebServer` capture tests, cumulative budget & Emergency Disconnect cancellation tests, `FLAG_SECURE` & `CharArray` UI cleanup tests, `SecretRedactor` export tests. **Zero live cloud calls or real cloud DNS queries.** | `android-unit-tests`, `android-lint`, `android-build`, `apk-validation` | Mandatory `PASS` for `FCT-004A` offline candidate. |
| **3. `FCT-004B` Governed `T4` Policy Transition Verification** | Isolated verification of separate `pilot` build (`INTERNET` only), preserved `offline` APK (`INTERNET`-free), and `apk_validator.py --connectivity-policy {offline,pilot}` negative tests under `TRANSITION_AUTHORIZATION`. | `apk-validation`, `harness-selftests` | Mandatory when `FCT-004B` transition PR is separately authorized. |
| **4. Authorized Physical-Device Live Pilot (`TEST-PILOT-414`)** | Human-supervised live read-only observation on authorized physical Android >= 12 device with dedicated test account & isolated `LaserSlam` robot. | `android-smoke-test` (external human-gated; `NOT_RUN` in offline CI) | Mandatory for `FCT-004` live pilot closure (`G7`/`G8`); never automated in CI. |

Per `C-004`, automated tests assert against independent literal origins, synthetic IPv4/IPv6 byte arrays, injected DNS/clock fixtures, `MockWebServer` captured requests/frames, and captured UI/diagnostic states — never invoking production helpers to compute expected values.
