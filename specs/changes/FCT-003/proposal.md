## 1. Problem Statement

Following `FCT-001` (clean-room `:app` foundation and build verification) and `FCT-002` (pure Kotlin robot control domain, synchronized `SimulatorRobotTransport`, and interactive Compose dashboard — closed as `ENGINEERING_CLOSED_WITH_DOCUMENTED_RUNTIME_LIMITATIONS`), the WeBack Android client remains strictly single-device and simulator-backed (`DefaultAppContainer`). Before a future hardware pilot (`FCT-004`) can ever be authorized to contact live Grit Cloud / AWS IoT endpoints, the project needs a clean-room, cryptographically hardened, specification-first baseline covering:

1. Account authentication contract, explicit endpoint trust & redirect isolation, region-routed session lifecycle, and dual-clock monotonic/persisted token expiry semantics.
2. Finalized Android Keystore AES-256-GCM Security ADR (`ADR-003`) completing [specs/tech-stack.md](../../tech-stack.md) §3.3 with cipher-generated 12-byte IVs, 128-bit GCM tags, canonical AAD, bounded record size, atomic replacement, fail-closed tamper/invalidation handling, hardware security-level verification plan (`KeyInfo`), and zero `EncryptedSharedPreferences`.
3. Cross-account/device `sessionEpoch` ownership across all asynchronous side effects, device inventory retrieval (`user_thing_list_get`), and deterministic `sub_type` capability classification grounded in `enums/p.java` and `utils/c.java`.
4. Cloud WebSocket connection lifecycle state machine, deny-by-default secret-safe logging & credential models (`SecretRedactor` as defense-in-depth), fault recovery, and dual **Offline Fixture** + hermetic **loopback `MockWebServer`** adapters.

Direct bytecode and decompiled Java inspection of the frozen legacy reverse-engineering artifacts (`com.yugong.Backome` 6.1.7) also confirmed material contradictions (`REG-06` through `REG-10`) alongside unresolved server-side behaviors that must be reconciled cleanly and quarantined prior to writing any production implementation code (`C-001`, `C-002`, `C-014`).

## 2. Objectives

1. **Reconcile & Quarantine Legacy Protocol Evidence (`REG-06`..`REG-10`):** Follow the strict Evidence Precedence Rule in [docs/reference/RE_BASELINE.md](../../../docs/reference/RE_BASELINE.md) §2.2 (Decompiled Bytecode > `protocols.json` > `final/*.md`), verify exact constants (`"login"`, `api_version` source, `language` source, `enums/p.java` + `utils/c.java` classifier sets, `20_000ms` WebSocket send-stall check), distinguish direct source observations from absence claims, and document archive provenance accurately.
2. **Establish T4 Endpoint Trust, Session Ownership & Time Semantics (`SEC-301`, `SEC-302`, `SEC-304`):** Enforce exact approved origin validation, disabled automatic redirects on credential-bearing HTTP clients, loopback-only `MockWebServer` destination verification, disabled production endpoint trust until `FCT-004`, unified in-process monotonic (`MonotonicClock`) vs persisted (`PersistedSessionRecord`) expiry/restart/reboot/rollback semantics without lifetime reset, and full `sessionEpoch` + `(sessionEpoch, connectionGeneration)` ownership across storage, caches, sockets, and telemetry.
3. **Finalize T4 Android Keystore AES-256-GCM ADR & Deny-by-Default Logging (`SEC-303`, `SEC-305`):** Specify cipher-generated 12-byte IVs, 128-bit tags, canonical AAD, `[29..16_384]` byte bounds, atomic write-temp-fsync-replace, fail-closed missing-key/invalidation/rotation/logout contracts, realistic mutable-buffer cleanup (without impossible immutable `String` zeroization claims), a real-device `KeyInfo.getSecurityLevel()` verification plan, and deny-by-default allowlisted logging with secret-safe `toString()` models.
4. **Enforce T4 Security Governance & Hermetic Offline Verification (`SEC-306`, `C-006`, `C-010`):** Repair all threat-to-oracle traceability links, separate automated offline/Robolectric verification from real-device `KeyInfo` (`NOT_RUN` when no authorized device is attached), preserve T4 manual UAT + dual-approval gates, reuse the 7-check policy (`policies/checks.json`) unmodified, keep `android.permission.INTERNET` excluded from `AndroidManifest.xml`, and maintain zero live network calls or real credentials.

## 3. Scope Boundaries

### 3.1 In Scope (Specification Scope -> Target Implementation Later Upon G3 Approval)
- Pure Kotlin authentication, endpoint trust contracts, session lifecycle, dual-clock token expiry/renewal, connectivity error, device inventory, and capability-detection domain contracts under `com.weback.robot.domain`.
- Security layer (`com.weback.robot.security`) threat model, Trust Boundaries, Keystore AES-256-GCM ADR & envelope specification, fail-closed corruption/invalidation/storage-error handling, `EndpointTrustPolicy` + `UriValidator`, deny-by-default diagnostic logging, and `SecretRedactor`.
- Network protocol contracts & clean-room adapters (`com.weback.robot.protocol`) for auth gateway, device inventory (`user_thing_list_get`), and cloud WebSocket lifecycle (`Connected`/`Disconnected`/reconnect/send-stall/error handling), implemented with both deterministic `OfflineFixture*` adapters and `OkHttp 4.12.0` + `kotlinx.serialization.json 1.7.3` adapters tested hermetically against loopback `MockWebServer 4.12.0`.
- Complete negative security test matrix (`TEST-AUTH-301..312`, `TEST-CONN-301..309`) and governance artifacts: `proposal.md`, `risk-assessment.md`, `requirements.md`, `design.md`, `validation.md`, `tasks.md`, and `traceability.json`.

### 3.2 Out of Scope (Explicit Non-Goals & Hard Prohibitions)
- **No FCT-003 Production Code or Dependency Changes in This PR:** This PR stops strictly at Gate G3 (`Implementation Readiness`); diffs stay strictly inside `specs/changes/FCT-003/` with zero Kotlin or Gradle changes.
- **No Live Network Calls, Production Refresh Grants, Legacy MD5 Wire Encoding, or Production Credentials (`C-010`, `C-013`):** Automated builds and tests must never contact `grit-cloud.cn`, `grit-cloud.com`, AWS IoT endpoints, or physical robots; optional refresh abstractions remain synthetic/disabled for production; legacy MD5 password transmission is not implemented in FCT-003; no real credentials enter Git or logs.
- **No Runtime `INTERNET` Manifest Permission in Offline Policy:** `verification/checks/apk_validator.py` prohibits `android.permission.INTERNET` under the active offline policy. FCT-003 keeps `AndroidManifest.xml` offline (`INTERNET`-free) and keeps production endpoint trust disabled until external `FCT-004` approval + isolated `T4` policy/manifest PR.
- **Excluded Hardware & Feature Domains (`specs/mission.md` §3.2–3.3):** ThroughTek camera/video (`CAT-03`, `libIOTCAPIs.so`, `libAVAPIs.so`), legacy XMPP Smack protocol runtime, smart sockets/thermostats/lamps/air-purifiers (`CAT-04`), BLE/SoftAP Wi-Fi provisioning (`FCT-008`), SLAM map rendering (`FCT-005`), actual robot hardware control, unnecessary UI expansion, and account registration/CAPTCHA automation.
- **No Modifications to Protected Governance Assets (`POL-INT-01`) or Frozen RE Workspace:** Zero edits to `policies/`, `verification/`, `.github/workflows/`, or the frozen external RE workspace.
