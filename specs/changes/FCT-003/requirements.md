### REQ-AUTH-301: Endpoint Trust Authorization, Region Routing, Redirect Isolation & Network Boundary
*(Workstream: `T4` — Auth/Endpoint Trust | Legacy Reconciliation: `REG-06`, `REG-10` | Security Calibration: `SEC-301`)*

The application must resolve authentication and session endpoints deterministically while enforcing explicit endpoint trust authorization, exact origin checks, strict redirect blocking, loopback test isolation, and standard TLS verification.

- **AC-301.1:** A pure Kotlin `RegionEndpointRouter` resolves China region codes (`"+86"`, `"0086"`, trimmed) to canonical CN auth URL (`"https://user.grit-cloud.cn/prod/oauth"` `[RE-OBSERVED: function/b.java:28, e0.java:144-149]`) and non-CN calling codes matching `^(\+|00)[0-9]{1,4}$` to canonical Global auth URL (`"https://user.grit-cloud.com/prod/oauth"` `[RE-OBSERVED: function/b.java:31]`) strictly when future cloud mode is explicitly enabled, while rejecting blank/malformed region codes before any I/O and keeping `FCT-003` test/offline configs isolated to loopback/fixture targets.
- **AC-301.2:** Clean-room `UriValidator` and `EndpointTrustPolicy` enforce explicit endpoint trust authorization before credential attachment: non-test `ProductionEndpointTrustPolicy` remains **disabled** (rejecting all live production origins without inventing production host allowlists until `FCT-004` approval); when evaluated against an authorized policy, endpoints MUST match exact approved origins (scheme + canonical lowercase host + explicit/default port, rejecting unapproved HTTPS/WSS hosts), MUST reject embedded `user:pass@` / `user@` userinfo, blank hosts, invalid ports, and credential-bearing query parameters or fragments; `TestLoopbackTrustPolicy` (`MockServerConfig`) binds `MockWebServer` clients strictly to explicitly configured loopback origins (`localhost`/`127.0.0.1`/`[::1]` + exact port), enforces `Proxy.NO_PROXY` (zero system proxy leakage), and validates resolved destination addresses are loopback (`InetAddress.isLoopbackAddress`), blocking any public DNS or external host fallback.
- **AC-301.3:** Credential-bearing HTTP clients (`OkHttpAuthGateway`, `OkHttpDeviceInventoryGateway`) MUST disable automatic redirects (`followRedirects(false)` and `followSslRedirects(false)`), treating any `3xx` response as an explicit non-followed `RedirectRejected` / `HandshakeRejected` failure without forwarding headers or credentials; standard TLS certificate and hostname verification MUST remain enabled with zero trust-all `TrustManager`/`HostnameVerifier`, zero process-global `HttpsURLConnection.setDefaultSSLSocketFactory`/`SSLContext.setDefault` overrides (`REG-10`), zero hardcoded test accounts/tokens, zero trackers, and zero proprietary P2P binaries (`C-010`, `C-014`).

### REQ-AUTH-303: Session Ownership, Epoch Isolation & Serialization Commit Contract
*(Workstream: `T4` — Auth/Session | Legacy Reconciliation: `REG-07` | Security Calibration: `SEC-304`)*

Session state and all asynchronous side effects must obey an explicit `sessionEpoch` ownership and persistence commit contract preventing duplicate calls, split-brain state, durable-logout false positives, and cross-account/device contamination.

- **AC-303.1:** `SessionStateMachine` and `SessionCoordinator` model mutually exclusive states (`SignedOut`, `Authenticating`, `Authenticated(session, epoch)`, `Refreshing(session, epoch)`, `ReauthenticationRequired(reason, epoch)`) using single-flight coroutine `Mutex` exclusion and a short-held `commitLock` for atomic in-memory state + `sessionEpoch` updates, NEVER holding locks across network I/O or backoff delays (`[CLEAN-ROOM-DESIGN]`).
- **AC-303.2:** Exact serialization and commit contract: `SessionCoordinator` routes actual persistent storage mutations (`save`, `clear`, `invalidation`, `key rotation`) through a **serialized persistence boundary** (`persistenceMutex` + epoch-fenced store operations; checking epoch before and after disk I/O alone is insufficient) without holding `commitLock` across network delays and protected against mid-cleanup cancellation (`NonCancellable` on invalidation/clear):
  - `signIn()` and synthetic `refresh()` abort stale `save()` if `sessionEpoch` changed before persistence execution and MUST NOT report durable `Authenticated` success if `TokenStore.save()` fails.
  - `signOut()` and forced invalidation immediately increment `sessionEpoch` under `commitLock` (blocking all in-memory credential use immediately), cancel pending auth/WS jobs, close active WebSocket transports, wipe inventory cache, selected device identity, and `RobotState`, and execute durable persistent invalidation (`TokenStore.clear()` + key/tombstone cleanup); `signOut()` NEVER reports durable logout success if `TokenStore.clear()` fails (`LogoutResult.IncompleteStorageClear`), and process restart after failed logout MUST fail closed to `ReauthenticationRequired` rather than silently restoring an invalidated record (`IC-302`).
- **AC-303.3:** `sessionEpoch` and persistence ordering govern ALL session-related asynchronous side effects (`TokenStore` save/clear/invalidation/rotation operations, concurrent `signIn`/`refresh`, logout during login or token persistence, Account A -> Account B switching, late HTTP auth/inventory responses, late `401`/`403` failure callbacks, inventory caches, selected device identity, WebSocket instances/reconnect jobs, and inbound telemetry); stale `save()` cannot resurrect credentials after logout, Account A saves cannot overwrite Account B credentials, stale `clear()` cannot delete Account B's newer record, and stale-epoch callbacks or results are discarded cleanly.

### REQ-AUTH-304: Dual-Clock Session Expiry, Restart/Reboot/Rollback Semantics & Passwordless Boundary
*(Workstream: `T4` — Auth/Session | Legacy Reconciliation: `REG-07`, `UNK-AUTH-01`, `UNK-AUTH-03` | Security Calibration: `SEC-302`)*

Token lifetime must follow unified dual-clock monotonic/persisted semantics without resetting lifetime on reload, trusting rolled-back wall clocks, parsing unverified JWT claims, or caching/replaying passwords.

- **AC-304.1:** `TokenExpiryPolicy` resolves `issuedAtElapsedMs` vs `issuedAtEpochMs`: Android authentication sessions use an authentication-specific monotonic clock (`AuthMonotonicClock` backed by `android.os.SystemClock.elapsedRealtime()`, including deep-sleep time; existing `MonotonicClock` / `SystemMonotonicClock` remains preserved for command timestamps and simulator timing, and `System.nanoTime()` MUST NOT be assumed sufficient for Android session expiry `IC-301`); in-process checks evaluate `SessionCredentials(expiresInSeconds > 0, issuedAtElapsedMs, priorElapsedMs = 0L)` with **checked `Long` arithmetic** across subtraction, addition, and multiplication (`checkedSub`/`checkedAdd`/`checkedMul`, failing closed on `expiresInSeconds <= 0L`, `priorElapsedMs < 0L`, `nowElapsedMs < issuedAtElapsedMs`, or any `Long` overflow near `Long.MAX_VALUE`); exact 80% proactive renewal triggers iff `elapsedMs > expiresInSeconds * 800L` (`false` at `800L * expiresInSeconds`, `true` at `+1ms` `[RE-OBSERVED: p0.java:368]`); exact expiration triggers iff `elapsedMs >= expiresInSeconds * 1000L`. `SessionCoordinator` and gateways MUST perform an immediate pre-send expiry/ownership check before sending any authenticated request and a post-response expiry/ownership check before applying any response.
- **AC-304.2:** Persisted `PersistedSessionRecord` stores `issuedAtEpochMs`, `lastSeenEpochMs`, `expiresInSeconds`, and optional same-boot anchor (`bootGenerationId`, `issuedAtElapsedRealtimeMs`) and NEVER resets token lifetime upon load: on a verified same-boot process restart (`bootGenerationId` matches, `nowElapsedRealtimeMs >= issuedAtElapsedRealtimeMs`, and wall clock did not roll back `nowEpochMs >= issuedAtEpochMs && nowEpochMs >= lastSeenEpochMs`), remaining lifetime is preserved via `priorElapsedMs = nowElapsedRealtimeMs - issuedAtElapsedRealtimeMs` (and transitions to `ReauthenticationRequired` if expired); on device reboot (`bootGenerationId` changed or absent, or `nowElapsedRealtimeMs < issuedAtElapsedRealtimeMs`) OR wall-clock rollback (`nowEpochMs < issuedAtEpochMs` or `nowEpochMs < lastSeenEpochMs`), `SessionCoordinator` adopts conservative `ReauthenticationRequired` and wipes stale bearer tokens. Unverified JWT claims (`exp`, `iat`, etc.) MUST NEVER be parsed or trusted for authorization or expiry decisions.
- **AC-304.3:** Optional `RefreshGrantStrategy` abstractions remain strictly synthetic and disabled for production (`DisabledPasswordlessRefreshStrategy`), so production expiry or auth rejection transitions deterministically to `ReauthenticationRequired`; when synthetically enabled in tests, single-flight refresh atomically updates `TokenStore` + `sessionEpoch`. Plaintext passwords and MD5 digests MUST NEVER be persisted or replayed (`C-010`, `C-014`).

### REQ-AUTH-305: Android Keystore AES-256-GCM Storage, Hardware Verification Plan & Deny-by-Default Logging
*(Workstream: `T4` — Cryptography & Privacy | Governance: [specs/tech-stack.md](../../tech-stack.md) §3.3, `C-010`, `REG-07`, `REG-09` | Security Calibration: `SEC-303`, `SEC-305`)*

Persisted session tokens must use non-exportable Android Keystore AES-256-GCM encryption with strict envelope/fail-closed guarantees, realistic hardware verification planning, deny-by-default logging, and defense-in-depth scrubbing.

- **AC-305.1:** `KeystoreAeadTokenStore` implements `TokenStore` via a non-exportable AES-256 key (`alias = "com.weback.robot.auth.session_key.v1"`) in `"AndroidKeyStore"` (`KeyProperties.KEY_ALGORITHM_AES`, `keySize = 256`, `BLOCK_MODE_GCM`, `ENCRYPTION_PADDING_NONE`, `PURPOSE_ENCRYPT or PURPOSE_DECRYPT`, `randomizedEncryptionRequired = true`), using **cipher-generated** IVs (`cipher.init(ENCRYPT_MODE, key)` with no caller IV; validating `iv.size == 12`), explicit `128`-bit GCM tag (`GCMParameterSpec(128, iv)`), canonical AAD (`"com.weback.robot:session:v1:01".toByteArray(UTF_8)`), bounded record size `[29..16_384]` bytes, and atomic write-temp-fsync-replace inside `context.noBackupFilesDir` (`android:allowBackup="false"`). `EncryptedSharedPreferences`, plaintext `SharedPreferences`, password/MD5 storage, and runtime software-key fallbacks are strictly prohibited (`C-010`).
- **AC-305.2:** Missing key with orphaned blob, `AEADBadTagException`, `KeyPermanentlyInvalidatedException`, record length `< 29` or `> 16_384`, bad schema version (`!= 0x01`), or post-decryption `PersistedSessionRecord` schema/`UriValidator` failure MUST fail closed by atomically deleting the corrupt blob (and deleting invalidated Keystore alias on key invalidation/rotation) and returning `TokenLoadResult.CorruptedOrInvalidated`; `save()` and `clear()` I/O failures MUST return explicit failure results without reporting durable success; mutable plaintext/ciphertext `ByteArray`/`CharArray` buffers MUST be zeroized in `finally` blocks (without claiming impossible zeroization of immutable JVM `String`s).
- **AC-305.3:** Adopt **deny-by-default logging** (`DiagnosticLogger` + allowlisted safe fields/categories, avoiding any broad global logging framework): normal execution paths MUST NEVER log auth request/response bodies, raw `token`/`authorization`/`cookie`/`set-cookie` headers, raw WebSocket payloads, passwords/digests, or unredacted credential-bearing exceptions, and credential model `toString()` / exception formatting MUST mask secrets. `SecretRedactor` provides defense-in-depth across case-insensitive sensitive headers, opaque tokens, `eyJ...` JWTs, nested and malformed JSON secrets, URL-encoded secrets, exception messages, and captured log sinks/verification artifacts.
- **AC-305.4:** Define security-level verification honestly (`IC-304`): pure-JVM JCA tests verify envelope/tamper/bounds logic and Robolectric verifies Android file/Keystore wiring (`android-unit-tests`), while neither proves TEE/StrongBox hardware protection. Real-device hardware-backed protection MUST be tested via an instrumentation test APK compiled cleanly (`./gradlew assembleDebugAndroidTest`) using an **isolated test Keystore alias and isolated storage namespace** (never touching live app session data) and inspecting `KeyInfo.getSecurityLevel()` (`SECURITY_LEVEL_TRUSTED_ENVIRONMENT` or `SECURITY_LEVEL_STRONGBOX`) on an explicitly authorized physical Android >= 12 device (`TEST-AUTH-312`), remaining explicitly `NOT_RUN` in offline CI when no authorized device is attached and blocking T4 hardware/release closure until executed alongside mandatory T4 manual UAT and dual approval (`SEC-306`).

### REQ-CONN-308: Cloud WebSocket Connection Lifecycle FSM, Send-Stall/Reconnect & Telemetry Ownership
*(Workstream: `T3` — Network Connectivity | Legacy Reconciliation: `REG-09`, `UNK-AUTH-06` | Security Calibration: `SEC-304`)*

The WebSocket transport adapter must enforce endpoint trust, generation-fenced lifecycle ownership, send-stall/reconnect timing, auth short-circuiting, and strict `thing_name` telemetry filtering.

- **AC-308.1:** `RealtimeSessionTransport` exposes reactive `StateFlow<ConnectionState>` (`Disconnected`, `Connecting`, `Connected`, `Reconnecting(attempt, retryDelayMs)`, `Closed`) with `(sessionEpoch, connectionGeneration)` fencing and short-held `commitLock` discipline (zero locks held across socket I/O or backoff sleeps `[CLEAN-ROOM-DESIGN]`).
- **AC-308.2:** `OkHttpWebSocketTransport` authorizes `wssUrl` via `EndpointTrustPolicy` + `UriValidator` and validates active session/expiry immediately before upgrade AND continuously while connected (`IC-303`: pre-send checks, inbound-frame expiry checks, and scheduled session-expiry deadline enforcement); attaches `"token"` and `"region"` HTTP headers (`[RE-OBSERVED: websocket/e.java:159-169]`, zero query tokens, `followRedirects(false)`, `followSslRedirects(false)`, `Proxy.NO_PROXY` + loopback DNS isolation in test mode); parses inbound JSON `notify_info == "thing_status_update"` frames (`[RE-OBSERVED: websocket/e.java:198,272-277]`), enforces injectable **send-stall detection** (`default 20_000ms`, matching `e.java:449-458` outbound stall check without claiming an unproven heartbeat contract) and bounded backoff reconnection (`default 4_000ms` base delay up to `maxReconnectAttempts`) via injected `DispatcherProvider` & `MonotonicClock`, and emits WebSocket close code `1000` on graceful `close()`.
- **AC-308.3:** Receiving HTTP `401`/`403` or `3xx` during handshake, an explicit invalid-token close, OR **session expiry / valid session invalidation while already connected** MUST immediately stop authenticated outbound activity, stop accepting inbound telemetry under expired authorization, cancel scheduled reconnect jobs, close/invalidate the affected socket, and trigger epoch-checked reauthentication coordination; idempotent `close()` cleanly rejects post-close mutations (`TEST-CONN-305`).
- **AC-308.4:** WebSocket instances and delayed reconnect jobs are strictly fenced by `(sessionEpoch, connectionGeneration)` so late `onMessage`/`onFailure`/`onClosing`/`onClosed` callbacks or queued reconnect timers from any superseded session or connection generation are discarded without mutating state or opening duplicate sockets (`SEC-304`). Unknown auth close codes and server-specific revocation payloads remain `[UNRESOLVED]` (`UNK-AUTH-06`).
- **AC-308.5:** Inbound telemetry MUST validate active `sessionEpoch`, `connectionGeneration`, selected device `thing_name`, and `MvpSupportedShadowWs` capability before applying state updates so unknown, unsupported, or unselected device frames NEVER mutate current `RobotState` (`SEC-304`).

### REQ-CONN-309: Dual Offline & Loopback `MockWebServer` Adapters and Manifest/Policy Boundary
