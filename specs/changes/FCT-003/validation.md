## 2. Hardware-Backed Keystore Verification Plan (`TEST-AUTH-312`)

- **Why Required:** Pure-JVM JCA tests and Robolectric verify envelope formatting, cipher-generated IVs, 128-bit GCM authentication, AAD binding, size bounds, atomic file replacement, and fail-closed error handling, **but neither JCA nor Robolectric proves TEE or StrongBox hardware backing**.
- **Real-Device Inspection Procedure (On Authorized Android >= 12 Physical Device):**
  1. Execute `KeystoreAeadTokenStore.save(...)` using the production `AndroidKeyStore` `AeadCipherProvider` (`alias = "com.weback.robot.auth.session_key.v1"`).
  2. Retrieve `SecretKey` from `KeyStore.getInstance("AndroidKeyStore")` and query `SecretKeyFactory.getInstance(key.algorithm, "AndroidKeyStore").getKeySpec(key, KeyInfo::class.java) as KeyInfo`.
  3. Assert `keyInfo.isInsideSecureHardware` awareness is superseded on `minSdk = 31` by checking `keyInfo.securityLevel == KeyProperties.SECURITY_LEVEL_TRUSTED_ENVIRONMENT || keyInfo.securityLevel == KeyProperties.SECURITY_LEVEL_STRONGBOX` (explicitly rejecting `SECURITY_LEVEL_SOFTWARE` and `SECURITY_LEVEL_UNKNOWN`).
  4. Verify key non-exportability (`key.encoded == null`), `keyInfo.blockModes` includes `GCM`, `keyInfo.encryptionPaddings` includes `NoPadding`, and `keyInfo.keySize == 256`.
  5. Test `KeyPermanentlyInvalidatedException` / key deletion + rotation recovery and confirm `session_record.bin` resides exclusively in `noBackupFilesDir` without backup exposure.
- **Offline CI Handling:** When no authorized physical Android >= 12 device is connected in CI, `TEST-AUTH-312` MUST retain status `NOT_RUN` (mapped to `device_dependent_not_run_count = 1`), explicitly blocking `FCT-003` T4 hardware/release closure until executed on hardware (`C-012`).
