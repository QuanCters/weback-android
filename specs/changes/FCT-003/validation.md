## 2. Hardware-Backed Keystore Verification Plan (`TEST-AUTH-312`)

- **Why Required:** Pure-JVM JCA tests and Robolectric verify envelope formatting, cipher-generated IVs, 128-bit GCM authentication, AAD binding, size bounds, atomic file replacement, and fail-closed error handling, **but neither JCA nor Robolectric proves TEE or StrongBox hardware backing**.
- **Real-Device Inspection Procedure (On Authorized Android >= 12 Physical Device):**
  1. Execute `KeystoreAeadTokenStore.save(...)` using the production `AndroidKeyStore` `AeadCipherProvider` with an **isolated instrumentation test Keystore alias** (`"com.weback.robot.auth.session_key.androidtest.v1"`) and **isolated storage namespace** (`noBackupFilesDir/androidtest_token_store`) so device tests cannot touch or destroy existing application session data (`IC-304`), verifying successful encrypted record persistence and `AEADBadTagException` tamper rejection.
  2. Retrieve `SecretKey` from `KeyStore.getInstance("AndroidKeyStore")` and query `SecretKeyFactory.getInstance(key.algorithm, "AndroidKeyStore").getKeySpec(key, KeyInfo::class.java) as KeyInfo`; assert `keyInfo.securityLevel == KeyProperties.SECURITY_LEVEL_TRUSTED_ENVIRONMENT || keyInfo.securityLevel == KeyProperties.SECURITY_LEVEL_STRONGBOX` (explicitly rejecting `SECURITY_LEVEL_SOFTWARE` and `SECURITY_LEVEL_UNKNOWN`), `key.encoded == null`, `GCM`, `NoPadding`, and `keySize == 256`.
  3. Delete ONLY the isolated test Keystore alias (`cipherProvider.deleteKey()` -> `KeyDeletionResult.Deleted`) while leaving the encrypted record on disk, confirm `!keyStore.containsAlias(testAlias)`, and verify `store.load()` fails closed rejecting the orphaned encrypted record (`MISSING_KEYSTORE_KEY`, explicitly distinguished from hardware biometric `KeyPermanentlyInvalidatedException`) and deletes it.
  4. Persist a fresh record via `store.save(...)`, confirming fresh key creation in hardware TEE/StrongBox and readable round-trip.
  5. Execute `store.clear()` and cleanup, verifying both the isolated Keystore alias and isolated storage files/directory are completely removed.
- **Compilation & Offline CI Handling (`IC-304`):** Pin instrumentation dependencies in `gradle/libs.versions.toml` and compile the instrumentation test APK (`./gradlew assembleDebugAndroidTest`) even when no authorized physical device is connected. Never automatically select arbitrary connected devices, and never claim hardware verification from JCA, Robolectric, or compilation; `TEST-AUTH-312` MUST remain `NOT_RUN` (`device_dependent_not_run_count = 1`) unless executed on an explicitly authorized physical Android >= 12 device, blocking `FCT-003` T4 hardware/release closure alongside mandatory T4 manual UAT and dual approval (`C-012`).
