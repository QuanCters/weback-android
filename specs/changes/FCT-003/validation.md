## 1. Verification Strategy & Policy Compliance

All `FCT-003` automated requirements are scoped to verify cleanly under the **existing 7-check policy** (`policies/checks.json`):
1. `spec-hygiene`: Validates cross-spec ID uniqueness (`REQ-AUTH-301..305`, `REQ-CONN-306..310`, `AC-301.1..310.3`), relative paths/anchors, and 100% `traceability.json` coverage.
2. `harness-selftests` & `gradle-wrapper-validation`: Confirm verification runner and pinned Gradle 8.10.2 integrity.
3. `android-unit-tests` (`gradle_test_adapter.py --task testDebugUnitTest` within `180s`): Executes pure Kotlin domain tests, JCA/Robolectric Keystore AES-256-GCM envelope tests, secret-redaction tests, virtual-time session/reconnect tests (`StandardTestDispatcher`), and local loopback `okhttp3.mockwebserver.MockWebServer` contract tests (zero live external network access).
4. `android-lint`, `android-build`, `apk-validation`: Confirm clean static checks, deterministic APK packaging, zero `com.yugong`/ThroughTek contamination, zero `EncryptedSharedPreferences`, and preserved offline manifest boundary (`no INTERNET permission` in offline `FCT-003`).

Per `C-004` (**Independent Test Oracles**), every test asserts against independently constructed literal envelopes, raw JSON strings, byte-level IV/tag checks, and `MockWebServer` recorded HTTP headers/bodies — never calling production helpers to derive expected outputs.

> **Separate Proposed Future Controls (Not Activated in Active Policy):** Before `FCT-004` live pilot execution, an isolated `T4` policy PR is proposed to add static `secret-redaction-lint` (scanning `MessageDigest.getInstance("MD5")`, `EncryptedSharedPreferences`, `setDefaultSSLSocketFactory`, cleartext header logs) and governed `android.permission.INTERNET` handling in `apk_validator.py`. Physical hardware/cloud execution remains strictly `NOT_RUN` unless separately authorized (`C-013`).
