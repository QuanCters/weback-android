## 1. Validation Strategy

Every FCT-002 requirement and acceptance criterion MUST be independently verified against the existing 7-check policy (`policies/checks.json`):
- **Specification & Schema Hygiene (`spec-hygiene`):** Enforces cross-spec ID uniqueness (`REQ-CTRL-201..208`, `AC-201.1..208.3`), portable paths, 100% traceability mapping, and valid existing check IDs.
- **Automated JVM & Compose UI Unit Tests (`android-unit-tests`):** Executes pure Kotlin domain unit tests, `TestScope`/`StandardTestDispatcher` coroutine transport & ViewModel contract tests, and Robolectric + Jetpack Compose UI tests via `./gradlew testDebugUnitTest` producing fresh JUnit XML telemetry parsed by `gradle_test_adapter.py`.
- **Static Analysis & Artifact Assembly (`android-lint`, `android-build`, `apk-validation`):** Enforces zero Lint errors/security regressions and clean APK packaging after FCT-002 code tasks begin.

Per `AGENTS.md` Verification Integrity Rule #3 (**No Mocking the Oracle**), test assertions compare actual state transitions, wire tokens, battery bounds, emitted `StateFlow` sequences, and Compose semantics against independently constructed expected tables/literals rather than re-invoking production helper formulas to compute expected results. Coroutine behavioral tests MUST use virtual time (`StandardTestDispatcher`/`runTest`) — zero wall-clock `Thread.sleep` waits.

## 3. Defect-to-Regression Commitment

Any defect uncovered during FCT-002 implementation or review MUST follow the mandatory 10-step lifecycle (`POL-INT-01`) before merging:
1. Assign unique `DEF-2026-NNN` record in `verification/defects.jsonl` with reproduction and root cause.
2. Add a failing (RED) unit/Compose test targeting the exact root cause.
3. Implement minimal clean fix -> observe GREEN -> verify verifier via mutation -> verify 7-check candidate pipeline.
